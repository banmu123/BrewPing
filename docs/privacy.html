Privacy Policy

Effective: September 18, 2026

BrewPing is a developer tool that lets you monitor and control the AI coding agents already running on your own computer, from your iPhone or Apple Watch, over your local network. This policy describes exactly what data BrewPing handles on each platform — and what it never sees. It is written against the actual behaviour of the shipping code, not a template.

1. Summary

We do not operate a server that receives your data. There is no account, no sign-up, no analytics, no crash-reporting SDK, no advertising identifier and no location collection in any BrewPing build.

Commands, agent output and voice transcripts travel only between your phone and the computer you configured, over your local network.

One exception exists, and it is yours to control: if you configure a model provider in the Windows desktop app, prompts and output are forwarded to that provider. See Third-party services below.

2. What this policy covers

This policy covers BrewPing on iOS, watchOS, macOS and Windows, and this website (commitbrew.com).

It does not cover the third-party coding agents you choose to run (OpenCode, Claude Code, Codex CLI, pi and others). Those are separate products with their own terms and privacy policies.

3. Information we do not collect

BrewPing contains no telemetry of any kind. Specifically, we do not collect:

  • Names, email addresses or contact details
  • Usage analytics, event tracking or screen recordings
  • Crash reports (the app contains no crash-reporting SDK)
  • Advertising identifiers — BrewPing never reads the advertising identifier, so no App Tracking Transparency prompt is needed
  • Location data — no Core Location usage, and no coarse or precise location is derived
  • Contacts, photos, calendar or health data

4. Data flow: iPhone and Apple Watch

Your device list and in-app preferences are stored on your iPhone in local app storage. The pairing token that authenticates your phone to your computer is stored in the iOS Keychain, not in plain app storage.

Commands you send are transmitted over HTTP on your local network to the host and port you configured (default 8787). They are not routed through any server of ours.

Agent output travels back along the same path and is rendered in the app.

5. Voice input and transcription

When you use voice input on Apple Watch, audio is recorded on the watch only while you are on the input screen, and is transferred to the paired iPhone over Apple's WatchConnectivity transport — a device-to-device channel, not an internet upload.

The iPhone then transcribes that audio file using Apple's Speech framework to produce the command text. Please note precisely how this works: BrewPing does not request on-device-only recognition, so transcription may be performed by Apple's servers rather than solely on your device. That transfer is between your device and Apple, is governed by Apple's own privacy policy, and we do not receive the audio or the transcript.

The temporary audio file is deleted from the iPhone immediately after transcription succeeds or fails.

6. Data flow: macOS desktop

The desktop app listens for your phone on port 8787 (falling back to 8788, then 8789 if the port is taken) and stores its state in ~/.brewping/:

  • session.json — current session id, process ids, working directory, status
  • agent.sock — a local Unix socket used by the command line tool
  • agent.log / opencode.log — agent standard output and error output
  • pairing.json — the pairing token, written with file permissions 0600
  • device.json — this computer's device identity
  • approval.json, config.json, workdirs.json — approval mode, agent and model preferences, working directory preferences
  • commands/ and conversations/ — one file per command, and stored conversations

7. Data flow: Windows desktop

The Windows app serves the same local HTTP API on port 8787 and stores its state under your user profile, in %USERPROFILE%\.brewping\:

  • device.json — device identity
  • pairing.json — the pairing token, file mode 0600
  • model_providers.json — provider configurations, proxy switch, proxy port, failover switch
  • workdirs.json — per-agent working directory preferences
  • approval.json — global approval mode

8. Bonjour and Local Network

BrewPing asks for Local Network permission for exactly one reason: to find and talk to the computer you have configured.

It browses and advertises the Bonjour (mDNS) service type _brewping._tcp on your own network. The advertised record carries the app version, the active agent id, the platform, a protocol version, and optionally a device id and device name — nothing else.

Discovery and command delivery both stay on your local network. There is no wide-area component: BrewPing does not open a connection to the internet to reach your computer, and it cannot be reached from outside your network unless you make your own network arrangements (for example Tailscale or WireGuard).

9. Relay server

No relay server is in operation. BrewPing ships as a local-network tool only.

For full transparency: the BrewPing source repository contains an experimental relay-server/ directory. It is not wired into any shipped client, it has no authentication, and the project documentation explicitly prohibits deploying it to the public internet or to any untrusted network. It is not built, not shipped and not running. If that ever changes, this policy will be updated before such a feature is enabled for anyone.

10. Third-party services

BrewPing embeds no analytics, advertising, attribution or crash-reporting SDK of any kind.

The one path by which your content can reach a third party is the one you configure yourself. The Windows desktop app can run a local model proxy on 127.0.0.1:15721. If you enable it and configure a model provider, the proxy forwards your prompts and the resulting output to that provider so the coding agent can do its work. The providers offered as presets are Kimi (Moonshot), DeepSeek, GLM (Zhipu), MiMo (Xiaomi) and MiniMax, plus a custom option where you enter the endpoint yourself. Which provider receives your content is entirely your choice, and that provider's own privacy policy governs what it does with it. We do not receive a copy.

Purchases of the iOS app are processed by Apple through the App Store. We do not receive payment card details. Apple provides us with aggregate sales and download reporting, and aggregate crash diagnostics only from users who have opted in to share diagnostics with developers.

11. This website

commitbrew.com is a static site hosted on Vercel. As with any public web server, Vercel may generate standard request logs (such as IP address, requested path and user agent) as part of delivering the pages.

We add no analytics, tag manager, advertising or cross-site tracking script to this site, and it sets no advertising or tracking cookies. The only thing this site stores in your browser is your language choice, kept in local storage so the site opens in the language you picked. Fonts are served from the site itself rather than from a third-party content delivery network.

12. Network requests, logs and errors

Traffic between your phone and your computer is plain HTTP on the local network. It is not encrypted with TLS on that local hop, which is why pairing is required: every request except the pairing exchange and a public status check must carry a bearer token, and write requests additionally carry a timestamp within a two-minute window plus a single-use nonce so a captured request cannot be replayed.

The apps log to the operating system's own logging facility. Command text, voice transcripts, file names and host names are all marked as private in those logs. Logs stay on your device and are never uploaded by us.

Error messages are shown to you in the app. We do not receive them.

13. How long data is kept, and how you delete it

Because we hold none of your data on any server, there is nothing for us to retain or delete. Retention is entirely on your own devices, and you control it:

  • Conversations and command history — delete them in the app, or activate a different conversation and clear the archive
  • Pairing token — removing the device in the app, or deleting the app, removes the Keychain item
  • macOS desktop state — delete ~/.brewping (this removes sessions, conversations, logs, preferences and the pairing token)
  • Windows desktop state — delete %USERPROFILE%\.brewping (this removes device identity, pairing token, provider configuration and working directory preferences)
  • Voice audio — deleted automatically right after transcription, whether it succeeded or failed
  • Uninstalling an app removes that app's own container and everything inside it

14. Your rights

Since we hold no account and no server-side copy of your data, we cannot access, correct, export or delete it for you — and we cannot hand it to anyone else, because we never receive it.

You therefore exercise these rights directly on your own devices, using the deletion steps above. Where a data protection law gives you rights over data we do not hold, there is simply no such data to act on.

If you believe any build of BrewPing is transmitting data it should not, please tell us. Point us at the specific behaviour and we will fix it rather than argue about it.

15. Children's privacy

BrewPing is a developer tool intended for people who already run coding agents on their own machines. It is not directed at children, and we do not knowingly collect information from anyone, including children.

16. Changes to this policy

If we change this policy, we will update the effective date at the top of this page. Because BrewPing does not hold your contact details, we cannot email you about changes — please check this page if the question matters to you.

17. Contact

Questions about this policy, or about what a specific build actually transmits: email czkbanmu@163.com, or open an issue on GitHub.

隐私政策

生效日期：2026 年 9 月 18 日

BrewPing 是一款开发者工具：让你通过 iPhone 或 Apple Watch，在局域网内查看并驱动已经运行在你自己电脑上的 AI 编程智能体。本政策逐平台说明 BrewPing 究竟处理了哪些数据、以及哪些数据它永远看不到。内容依据实际发布的代码行为撰写，而非套用模板。

1. 概要

我们不运营任何接收你数据的服务器。所有 BrewPing 版本中都没有账号、无需注册、无数据分析、无崩溃上报 SDK、无广告标识符，也不采集位置。

指令、智能体输出与语音转写结果，只在你自己的手机与你配置的电脑之间通过局域网传输。

存在一个例外，且完全由你掌控：如果你在 Windows 桌面端配置了模型服务商，提示词与输出会被转发给该服务商。详见下文「第三方服务」。

2. 适用范围

本政策覆盖 iOS、watchOS、macOS、Windows 上的 BrewPing，以及本网站 commitbrew.com。

它不覆盖你自行选择运行的第三方编程智能体（OpenCode、Claude Code、Codex CLI、pi 等）。那些是独立产品，适用它们各自的条款与隐私政策。

3. 我们不收集的信息

BrewPing 不含任何形式的遥测。具体而言，我们不收集：

  • 姓名、邮箱或联系方式
  • 使用分析、事件埋点或屏幕录制
  • 崩溃报告（App 内不含崩溃上报 SDK）
  • 广告标识符——BrewPing 从不读取广告标识符，因此无需 App 跟踪透明度弹窗
  • 位置数据——未使用 Core Location，也不推导任何粗略或精确位置
  • 通讯录、照片、日历或健康数据

4. 数据流：iPhone 与 Apple Watch

你的设备列表与应用内偏好保存在 iPhone 本地存储中。用于向你的电脑证明手机身份的配对令牌存放在 iOS 钥匙串（Keychain），而非普通应用存储。

你发送的指令通过局域网 HTTP 传输到你自己配置的主机与端口（默认 8787），不经过我们运营的任何服务器。

智能体输出沿同一路径返回，并在 App 中渲染。

5. 语音输入与转写

当你在 Apple Watch 上使用语音输入时，音频仅在你停留在输入界面期间于手表上录制，并通过 Apple 的 WatchConnectivity 通道传输到已配对的 iPhone——这是设备到设备的通道，不是互联网上传。

随后 iPhone 使用 Apple 的 Speech 框架转写该音频文件，得到指令文本。这里需要准确说明：BrewPing 并未请求「仅设备端识别」，因此转写可能由 Apple 的服务器完成，而不完全在你的设备上完成。该传输发生在你的设备与 Apple 之间，适用 Apple 自己的隐私政策；我们不会收到音频或转写内容。

转写成功或失败后，该临时音频文件会立即从 iPhone 上删除。

6. 数据流：macOS 桌面端

桌面端在 8787 端口监听来自你手机的请求（端口被占用时依次回落 8788、8789），并把状态存放在 ~/.brewping/ 目录中：

  • session.json —— 当前会话 id、进程 id、工作目录、状态
  • agent.sock —— 命令行工具使用的本地 Unix socket
  • agent.log / opencode.log —— 智能体的标准输出与错误输出
  • pairing.json —— 配对令牌，以 0600 权限写入
  • device.json —— 本机设备身份
  • approval.json、config.json、workdirs.json —— 授权档位、智能体与模型偏好、工作目录偏好
  • commands/ 与 conversations/ —— 每条命令一个文件，以及已保存的对话

7. 数据流：Windows 桌面端

Windows 端同样在 8787 端口提供本地 HTTP API，并把状态存放在用户主目录下的 %USERPROFILE%\.brewping\：

  • device.json —— 设备身份
  • pairing.json —— 配对令牌，文件权限 0600
  • model_providers.json —— 服务商配置、代理开关、代理端口、故障转移开关
  • workdirs.json —— 各智能体的工作目录偏好
  • approval.json —— 全局授权档位

8. Bonjour 与本地网络

BrewPing 申请「本地网络」权限只有一个原因：发现并与你自己配置的那台电脑通信。

它在你自己的网络中浏览并广播 Bonjour（mDNS）服务类型 _brewping._tcp。广播记录只包含应用版本、当前激活的智能体标识、平台、协议版本，以及可选的 device id 与 device name——除此之外没有别的内容。

设备发现与指令投递都留在你的局域网内。没有任何广域组件：BrewPing 不会为了连上你的电脑而主动发起互联网连接；除非你自行组网（例如 Tailscale 或 WireGuard），否则外部也无法触达它。

9. 中继服务器

当前没有任何中继服务器在运行。BrewPing 只作为局域网工具发布。

为完全透明起见需要说明：BrewPing 源码仓库中存在一个实验性的 relay-server/ 目录。它没有接入任何已发布的客户端，没有鉴权，且项目文档明确禁止将其部署到公网或任何不可信网络。它没有被构建、没有被打包、也没有在运行。若这一点将来改变，我们会在向任何人启用该功能之前先更新本政策。

10. 第三方服务

BrewPing 未内置任何分析、广告、归因或崩溃上报 SDK。

你的内容流向第三方的唯一路径，是你自己配置的那条。Windows 桌面端可以在 127.0.0.1:15721 运行本地模型代理。若你启用它并配置了模型服务商，代理会把你的提示词与相应输出转发给该服务商，以便编程智能体完成工作。内置预设服务商为 Kimi（月之暗面）、DeepSeek、GLM（智谱）、MiMo（小米）、MiniMax，另有「自定义」项供你自行填写端点。由哪个服务商接收你的内容完全由你决定，该服务商自身的隐私政策决定它如何处理这些数据。我们不会收到副本。

iOS 版 App 的购买由 Apple 通过 App Store 处理。我们不会收到支付卡信息。Apple 会向我们提供聚合的销售与下载报表，以及仅来自选择向开发者共享诊断信息的用户的聚合崩溃诊断数据。

11. 本网站

commitbrew.com 是部署在 Vercel 上的静态站点。与任何公共 Web 服务器一样，Vercel 在分发页面时可能会产生标准的请求日志（例如 IP 地址、请求路径与 User-Agent）。

本站点未添加任何分析、标签管理、广告或跨站跟踪脚本，也不设置广告或跟踪 Cookie。站点在你浏览器中存储的唯一内容是你的语言选择，保存在本地存储里，以便下次打开时沿用你选的语言。字体由站点自身提供，而非第三方 CDN。

12. 网络请求、诊断日志与错误信息

你手机与电脑之间的流量在局域网上是明文 HTTP，这一段没有 TLS 加密。这正是需要配对的原因：除配对交换与一个公开的状态查询外，每个请求都必须携带 Bearer 令牌；写请求还要额外携带两分钟时间窗内的时间戳与一次性 nonce，使被截获的请求无法重放。

各端日志写入操作系统自身的日志系统。命令原文、语音转写结果、文件名与主机名在这些日志中均标记为 private。日志留在你的设备上，我们从不上传。

错误信息直接显示在你的 App 内。我们不会收到这些错误信息。

13. 数据保存期限与删除方式

由于我们不在任何服务器上持有你的数据，因此不存在由我们保存或删除的内容。留存完全发生在你自己的设备上，由你掌控：

  • 对话与命令历史 —— 在 App 内删除，或切换/清空归档
  • 配对令牌 —— 在 App 中移除设备，或卸载 App，即可删除钥匙串条目
  • macOS 桌面端状态 —— 删除 ~/.brewping（会清除会话、对话、日志、偏好与配对令牌）
  • Windows 桌面端状态 —— 删除 %USERPROFILE%\.brewping（会清除设备身份、配对令牌、服务商配置与工作目录偏好）
  • 语音音频 —— 转写结束后自动删除，无论成功或失败
  • 卸载某个 App 会移除该 App 自身的容器及其中的全部内容

14. 你的权利

由于我们不持有账号，也不在服务器端保存你的任何数据副本，我们无法为你访问、更正、导出或删除这些数据——同样也无法把它们交给任何第三方，因为我们从未收到过。

因此，你可以直接在自己的设备上、使用上文的删除步骤行使这些权利。若某部数据保护法律赋予你针对数据的权利，而我们并不持有该数据，那么客观上不存在可处理的数据。

如果你认为 BrewPing 的某个版本在传输它本不该传输的数据，请告诉我们。请指出具体行为，我们会去修复它，而不是争辩。

15. 儿童隐私

BrewPing 是面向已经在自己机器上运行编程智能体的开发者的工具，并非面向儿童。我们不会有意收集任何人（包括儿童）的信息。

16. 政策变更

若本政策发生变更，我们会更新本页顶部的生效日期。由于 BrewPing 不保存你的联系方式，我们无法通过邮件通知你——如果这件事对你重要，请自行查看本页。

对本政策、或对某个具体版本实际传输了什么有疑问：请发邮件至 czkbanmu@163.com，或在 GitHub 提交 Issue。
