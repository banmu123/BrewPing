## 按钮全局内边距 + 空态居中（用户审核反馈，0870801）

用户审核指出两问题：① 空态问候（☕ + 待命中）不垂直居中；② 所有按钮"没有边距像塞在里面"。

**根因**：
- `LatteButtonStyle.makeBody` **零内边距**（label 直接贴背景/描边）→ 全站按钮都像裸文字。
- `LandingGreeting` 是 ScrollView，内容无最小高度 → 顶在页首。

**修法（仅 Mac）**：
- 按钮样式加 `Size`：`regular`（文本，12/5）/ `icon`（方形图标钮，6/6，调用处去掉手工 frame）；
  字号尊重调用处（原来强制 `LatteFont.sm` 会盖掉调用处的 xs）；补 `contentShape` 整块可点。
- 空态：内容 `.frame(minHeight: viewport.height)`（GeometryReader 取视口高）→ 不足一屏居中、超长可滚。
- 同批：转发代理摘要卡展开按钮文案与标题重复（"转发代理"×2）→「代理设置」+ 上下箭头。

**长期约定（MEMORY.md 已记）**：新增文本按钮不传 size（默认 regular 即有边距）；
**纯图标按钮必须 `size: .icon`** 且不要再套 `.frame(width:height:)`。

release `.app` 已重打启动供用户复检。

## 工作目录 Mac→iOS 同步修复（66ca9ee）

用户报告：Mac 选的目录 iOS 看不到，iOS 也没有切换入口。

### 定位（两端并行盘点）
1. **Mac HTTP 层缺 3 条路由**（iOS 目录浏览器全 404，这是"无法切换"的直接原因）：
   `GET /api/folders/roots`、`GET /api/folders`、`POST /api/agents/workdir` ——
   `FolderBrowser`/`WorkdirPrefs` 底层早已实现（桌面 composer 在用），只缺 HTTP 暴露。
2. **`GET /api/agents` 不带 workdir**：iOS 的 `AgentEntry.workdir` 与 Demo 桩契约早预留，
   真端点没给 → iOS 做不了 Agent 级回落显示（"看不到当前目录"）。
3. **iOS 详情页无覆盖轮询** + workdirBar 只读对话级不可点 + 5s 状态循环只刷 status
   不刷 agents → Mac 改了 iOS 永远看不到。

### 关键实现点（踩坑）
- 🚨 **HTTPRequest 把 `?` 后的 query 整段丢弃**（HTTPServer.swift parseHead）——带参 GET
  根本无法实现。已补 `query: String?` + `queryItems` 解析，并穿透 receiveBody 递归。
- 🚨 **hidden 过滤必须在分页之后**：下一页 offset 基于未过滤页宽，否则翻页跳条目。
- 🚨 **POST /api/agents/workdir 先校验再写入**：`WorkdirPrefs.set` 的语义是
  "normalize 失败 = 移除偏好"，HTTP 层不拦的话非法路径会把既有偏好顺手清掉 → 回 400 path-invalid。
- 🚨 iOS `ConversationDetail` 覆盖字段是 `let` → refreshOverrides 要 merge 就得 `var`。
- 🚨 iOS `refreshAgents` 失败路径会清空 agents → 直接放进 5s 循环会把网络抖动放大成
  界面清空；用非破坏性包装（失败且非 401 时回滚旧值）。
- 🚨 heredoc 里 Python 写 `\\n` 是字面量反斜杠+n（strings 文件差点被写坏，od 抓到后修复）。
- xcodebuild 用 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` 可绕过
  xcode-select 指向 CLT 的限制（本机装了 Xcode.app 但默认工具链是 CLT）。
- iOS 错误码契约：path-invalid / unknown agent / "does not support workdir"（opencode），
  与 `FolderBrowserStore.workdirErrorMessage` 的映射逐条对齐。

### 同步链路（修后）
- Mac 对话级换目录（composer 绑定已有对话）→ PATCH workdir → iOS 详情页 5s 轮询
  `refreshOverrides`（只 merge 覆盖字段不动 messages）→ workdirBar 更新。
- Mac 草稿态/Agent 级换目录 → WorkdirPrefs → `/api/agents` workdir 字段 →
  iOS 5s 循环 `refreshAgentsKeepingOldData` → workdirBar 回落显示更新。
- iOS 主动切换：详情页 workdirBar（可点）→ FolderBrowserView 对话级绑定 → PATCH → 同链；
  解绑在 sheet 底部。

### 验证
- Mac：swift build ✓；release 端到端 curl —— roots / folders(path+hidden / /tmp+hidden=1 /
  无参回落主目录) / agents.workdir / POST 绑定✓ 非法路径 400 path-invalid ✓ 清除✓。
- iOS：xcodebuild（iPhone 16 Pro 模拟器）**BUILD SUCCEEDED**（两轮抓出 onChanged 越界
  与 let 字段两处编译错并修复）；本地化校验脚本 ✓（en=zh=216）。
- release `.app` 已带新路由运行中（curl 实测即来自该实例）。

## 目录浏览器「无法下钻」交互重做（iOS）+ macOS 枚举失败诚实化

用户报告：部分目录点击后不进入、直接弹确认框。

**根因**：`FolderBrowserView` 行点击 = `pendingSelection = entry`（弹确认框），
**没有任何下钻动作**（`store.enter` 从未被行点击调用）。不是"部分目录"的问题——
是所有目录都不能点进去；感知差异来自用户先靠手输路径/上级进了某层。
次要因素：macOS `FolderBrowser.browse` 枚举失败 `try?` 吞成空列表（TCC 目录
等会被误判为空目录）——已改为抛 permissionDenied → HTTP 403（iOS 有锁态 UI）。

**交互重做（iOS FolderBrowserView）**：
- 行点击 = 下钻（store.enter）；行尾并列 ✓ 按钮 = 直接选（确认框流程不变）；
- `.empty` 空态 ContentUnavailableView 加 actions「选择此目录」（selectCurrentFolder
  助手：onPick 对话级 / setWorkdir Agent 级两分流与 Set Here 一致）；
- 不可读目录两动作都禁用；新文案 Select This Folder（en/zh）。

**验证**：xcodebuild BUILD SUCCEEDED；macOS chmod 000 目录 → 403 permission-denied、
常规目录 200 回归通过。另：curl 排查时确认本机 Desktop/Documents/Downloads 可正常
枚举（TCC 未拦截该 app），"部分目录"感知纯由交互缺陷造成。
