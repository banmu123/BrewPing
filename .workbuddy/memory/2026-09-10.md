# 2026-09-10

## BrewPing Desktop（macOS，SwiftPM）Dock 图标修复

**问题**：Dock 里 BrewPing Desktop 是一个硬角白底方块，与系统图标（圆角 squircle）不一致。

**定位过程与结论**
- 图标资源在 `build/BrewPing Desktop.app/Contents/Resources/AppIcon.icns`，由 Info.plist 的
  `CFBundleIconFile=AppIcon` 指向。该 icns 是「透明底 + 悬浮咖啡杯」，没有 macOS 圆角底板。
- icns 内部元数据 `info` 块写着 `assetcatalog-reference` → 来自 Xcode 资源目录导出（很可能源自
  iOS 的 `AppIcon-1024.png`，那份是 mode=RGB 的不透明白底图，是白底方块的典型来源）。
- 用「同一份 icns 放进新 bundle id 的探针 .app」做 A/B：探针渲染正常 → 原路径上的
  **IconServices 图标缓存是脏的**，白底方块来自历史缓存而非当前 icns 内容。
- 真正的隐患：`build-app.sh` 完全不处理图标（既不拷 icns 也不写 CFBundleIconFile），
  且默认写 `LSUIElement=true`（纯菜单栏、不显示 Dock 图标）。`build/` 里那个带图标的 bundle
  不是这个脚本产出的。

**改动**
- 新增 `tools/make-appicon.py`：从 `logo/logo.png` 生成 macOS squircle 母版
  （超椭圆 n=5，1024 画布 / 824 底板 / 四角透明；抠图去白边 + 收紧 alpha + 底部接触阴影；
  底板用浓咖啡渐变，因浅色底板在 46pt 下主体不可辨）。
- 新增母版资源 `logo/AppIcon-1024.png`（espresso 配色）与可直接拷贝的 `logo/AppIcon.icns`。
- `build-app.sh`：新增 `APP_ICON="logo/AppIcon.icns"` 拷贝到 Resources、plist 写入
  `CFBundleIconFile=AppIcon`、`touch` 让缓存失效；`LSUIElement` 改为 `SHOW_IN_DOCK` 开关（默认 1）。
- 重新打包了 `build/BrewPing-Desktop-0.1.0.dmg`（旧包内还是白底图标），旧包备份在
  `/tmp/BrewPing-Desktop-0.1.0.dmg.bak`，旧 icns 备份在 `/tmp/AppIcon.old.icns`。
- 新增对比预览 `logo/AppIcon-preview.png`。

**验证**：`./build-app.sh` 端到端通过（沙箱内需 `--disable-sandbox`），产出的 bundle
Resources 内有 icns、plist 有 CFBundleIconFile、无 LSUIElement；Dock 实拍已是圆角 squircle。

**遗留 / 待确认**
- `build-app.sh` 写的 bundle id 是 `local.brewping.desktop`，而手工装的旧 bundle 是
  `com.brewping.desktop`。全仓没有引用，暂未统一。
- `Sources/BrewPingwinDesktop/src-tauri/icons/` 仍是 Tauri 默认占位图标（icon.ico 仅 174B），
  Windows 侧还没接品牌图标。
- iOS / Watch 侧 `AppIcon-1024.png` 是不透明白底图，iOS 自动裁圆角所以正常；若要统一品牌观感
  可考虑换成分级更高的设计稿。
