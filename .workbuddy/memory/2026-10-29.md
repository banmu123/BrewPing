# 2026-10-29 — iOS 命令可靠性优化（状态机 / 测试 / 列表 / 扫码）

## 本轮交付
- 新增 `Sources/Protocol/CommandLifecycle.swift`（public，纯逻辑）：`CommandPhase`（新增
  `.awaitingApproval` / `.trackingApproval`）、`CommandChannel`（提交通道 + `runToken` 世代）、
  `CommandPollRules`（HTTP/状态 → 下一步、拾取看门狗 90s）。
- iOS target 通过 pbxproj 里 `../Sources/Protocol` 分组接入该文件（新增 ID 用 `CC0000…` 前缀，
  原工程只有 AA/BB 前缀，避免撞号），因此**不需要新建 Xcode test target** —— 单测走 SwiftPM，
  CI 的 `swift test` 已覆盖。
- `CommandSubmitter`：提交返回 Bool；通道被占用时拒绝并给 Watch 回失败终态；审批等待不再置 idle；
  关窗转 `.trackingApproval` 并轮询 `/api/approvals`（消失后用对话转录里的新 commandId 认领结果，
  认不到就明确失败，绝不假装成功）；所有 await 后校验 `channel.isCurrent(token)`，切设备/重置后
  旧回调不写 UI；`reopenPendingApproval()` 支持从提示条点回审批弹窗。
- 详情页：`canSend` 纳入 `isBusy`；忙碌时按钮显示 ProgressView + 输入框上方提示条；
  草稿延迟到 `.delivered` / `.awaitingApproval` 才清，失败保留原文。
- 列表：前台 25s 低频同步（`.task(id: "\(scenePhase)-\(online)")`），后台/离线自动停；
  `ConversationStore.refresh` 加 `isRefreshing` 去重 + `refreshGeneration` 丢弃过期回包；
  错误行加 Retry。
- 扫码：`AVCaptureSession` 全部操作移到专用串行队列，元数据回调也在该队列；预览层回主线程；
  新增「Try Again」（非权限错误时重建 representable）。
- 测试：`Tests/BrewPingCoreTests/CommandLifecycleTests.swift` 25 例（状态转移 17 + 轮询规则 8），
  Swift 总数 119 → **144**；`docs/PROJECT_STATUS.md` §3 已同步。
