## 🎯 Android CI 真因（失败自证机制立刻生效）

加了注解提炼后，run #10 的注解直接给出真错误：
`Gradle assembleDebug failed (exit 1)` / `Caused by: java.lang.ClassNotFoundException: "-Xmx64m"`

**根因**：`Android/gradlew` 是**手写精简版**（94 行/2274B，官方 Gradle 8.14 生成的是
251 行/8755B），末行 `exec "$JAVACMD" $DEFAULT_JVM_OPTS ...` 未加引号展开变量，而
`DEFAULT_JVM_OPTS='"-Xmx64m" "-Xms64m"'` 里**带引号** —— shell 的引号移除发生在展开
**之前**，于是 JVM 收到字面量 `"-Xmx64m"`（含引号）→ 不被识别为选项 → 当成主类名 →
ClassNotFoundException。官方脚本靠 `xargs + sed + eval` 二次解析剥离引号。
🚨 **与平台无关**：macOS 上直接跑 `./gradlew` 同样会挂；一直没暴露是因为 Android Studio
走 Gradle Tooling API、不执行 gradlew 脚本。
**修**（f3f4738）：用官方 v8.14.0 的 gradlew/gradlew.bat 替换（cmp 逐字节一致），保持
git 索引 100755。官方脚本还有额外好处：fd 提升、MSYS/Cygwin 路径转换、xargs 存在性检查。
📌 教训：**手写的构建脚本要 diff 官方生成版**；`$VAR` 不带引号展开时，变量值里的引号不会被剥离。

## 🎯 Windows 最后一个失败用例：8.3 短名 vs 长名（断言太字面）

GitHub runner 的 `%TEMP%` 是**短名形式** → `std::env::temp_dir()` 拿到短名；

**产品行为正确**（子进程确实跑在设定目录），是**测试断言过于字面**。

（App 自己的 realpath + 剥 `\\?\` 规范化）再比，断言强度不变（仍是完整路径一致），
只是不再受字面形式干扰；失败信息也带上实际响应更易诊断。

📌 **Windows 通用教训**：同一目录可有长名 / 8.3 短名 / `\\?\` 前缀等多种合法字面形式，
**比较路径前必须先规范化**（realpath），不要对撞原始字符串。同类坑还有 junction/symlink
（`canonicalize` 会解析、`%CD%` 不会）。

## 22:00 iOS TestFlight 自动发现失效 —— 定位（未改代码）
