## iPhone 自动发现扫不到设备（多播不通，单播可通）

用户报告：桌面端在跑、手动输 IP 能连，但「附近电脑」列表为空。
**排查结论：Mac 端广播正常**（`dns-sd -B _brewping._tcp` 实测可见实例名；
`BonjourAdvertiser.swift` 无问题），问题在 iPhone↔Mac 的多播路径。
成因优先级：① **iPhone「本地网络」权限未开**——iOS 管控 Bonjour 浏览与 .local
解析，但**直连 IP 字面量不受限**，故「手动能连、自动扫不到」是典型症状；
② 路由器 AP 隔离 / 访客网络 / 跨网段拦多播（本机 Mac IP 常变：192.168.5.9 →
192.168.1.226，需核对 iPhone 是否同网段）；③ iPhone 端 VPN。
**本机 Mac 有 5 个 utun 接口**（疑似 Tailscale 类工具），默认路由仍是 en0，非全隧道。
**改**：nearbyCard 增 else 分支 → discoveryHintCard（同一网段 + 本地网络权限路径
+ 多播被拦说明 + 「手动输入 IP」按钮直连已有流程），仅在搜过一轮空手而归时出现。

## Watch 对话页自动刷新修复（Mac 已回复但手表停在 loading）

根因：手表详情页只有 onAppear + 手动 Refresh 两个刷新时机；iPhone 仅在
**手表来源**命令完成时推 commandResult（且与落库有竞态），Mac/iPhone 来源
命令零推送 → 手表必然停在旧转录/loading。
**修**：① `requestConversation(id:silent:)` 静默模式（屏上已有内容时不闪
loading、失败不覆盖旧内容）；② 详情页停留期间每 5s 静默轮询（Timer +
onDisappear 清理，unreachable/detailLoading 中跳过），覆盖全部命令来源；
composer 完成时的即时刷新保留作双保险。
**注意**：需重打 TestFlight build 3（或 Xcode 直装）才在手表上生效。
另一个确认中的问题：手机「本地网络」权限弹窗一闪而过被丢弃 → 让用户去
设置 → 隐私与安全性 → 本地网络 手动开（iOS 被拒后不再弹窗）。
