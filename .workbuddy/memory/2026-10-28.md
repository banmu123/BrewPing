# 2026-10-28 — HTTP 解析加固 + 配对码限速（第一批安全优化）

## 本轮交付
- `Sources/App/HTTPServer.swift`：`parseHead` 改为 `Result<ParsedHead, HeadParseFailure>`，严格校验
  Content-Length（负数/非数字/重复/超 8MB）、拒绝任何 Transfer-Encoding、请求行必须 3 段 + HTTP/1.0|1.1、
  拒绝 obs-fold 与控制字符；头部 >1MB → 431（无论 CRLFCRLF 是否到达）。删除 `Int(value) ?? 0` 的静默降级。
- `HTTPRequest.remoteAddress`（新增可选字段，默认 nil）：来自 `NWConnection.endpoint`，实测入站即远端
  （E2E 断言得到 "127.0.0.1"），**不用 X-Forwarded-For**。中继隧道请求为 nil。
- `HTTPResponse.headers`（新增，默认 [:]）+ `respond` 输出额外头（过滤 CR/LF），用于 429 的 Retry-After。
- `PairingStore`：`ExchangeResult{token|invalidCode|rateLimited(retryAfter)}`；注入 clock + RateLimitPolicy；
  单来源 5 次/5 分钟 → 冷却 60s，全局 30 次/5 分钟 → 冷却 60s；状态上限 256 来源、按窗口 prune；
  无活跃配对码时**不计**失败（防预先打满全局冷却）；成功后清该来源记录。
- 测试：`HTTPParsingTests`(33) + `PairingRateLimitTests`(19)，Swift 66 → **118** 全绿。
  含真起 NWListener + 裸 socket 的 E2E（负数 CL 不再 `prefix(-1)` 崩溃、同包/分包、超限头体）。

## 踩到的坑（重要）
- 🚨 **`cargo test` 在 macOS 上会失败**：`services/folder_browser.rs` 测试体调用 `#[cfg(windows)]` 的
  `set_hidden_attr` → 无法编译。属既有平台限制（CI 在 windows-latest 跑）。
- 🚨 **`cargo test` 会在 `Sources/BrewPingwinDesktop/src-tauri/target/` 生成 2.1GB 产物**，
  而 SwiftPM target 的 path 就是 `Sources` → 扫到 crate 里的 C 源码 → 报
  「contains mixed language source files」。**跑完必须 `cargo clean`**，否则 swift build/test 全挂。
  同一原因：tauri 构建脚本还会生成未跟踪的 `gen/schemas/macOS-schema.json`，已删。
- 本机 `swift build` 不带 `--disable-sandbox` 会 `sandbox-exec: sandbox_apply: Operation not permitted`
  （SwiftPM 自身沙箱），本地一律加该参数；CI 不加。

## 兼容性结论
iOS URLSession / Android OkHttp / Mac 本机调用都发 Content-Length、不带 TE、不带重复 CL，行为不变。
429 是新增状态；客户端未改（iOS 直接展示服务端英文 error，与既有 401 同款，本地化缺口另行处理）。

## 第二批：安全审计 + 两套方案（纯文档，未改协议）
- 产出：`docs/BrewPing-安全审计-第二批.md`（418 行）、`docs/BrewPing-安全传输方案.md`（290 行）、
  `docs/BrewPing-设备授权与撤销方案.md`（289 行）。提交 `e45db13`。
- 风险口径：P0×1（明文 HTTP 传 Bearer）、P1×4（无设备级吊销 / 审批档位可远程置 auto /
  always-allow 无撤销入口 / relay 明文）、P2×9（含 status 泄露、Windows 无限速、Android 全局明文、
  GET 有副作用、无轮换、跨端细节、无设备归因审计、pending 内存态、转录文件 644）。
- 审计新增确认事实：①客户端「移除设备」两端都只删本地（DeviceStore.swift:40 / DeviceStore.kt:74），
  桌面端无设备表、无吊销端点；②`/api/pair` 收到 `deviceName` 但从未读取；
  ③**axum 0.8 `route_layer` 不覆盖 fallback**（path_router.rs:311-341）→ Windows 未知路径免鉴权，
  macOS 是路由前判定（401），已归入 P2-06；④`~/.brewping` 755 + `conv_*.json` 644，
  `~` 是 750（staff 可穿越）→ 同组本地用户可读转录，`pairing.json` 0600 不受影响。
- 方案要点：传输选 TLS1.3 + 每装机唯一自签证书 + SPKI 固定 + **配对码作 SAS 绑定**
  （`binding = HMAC(code, spki‖clientNonce)`，解决首次配对 MITM）；设备授权用 `bp1.<deviceId>.<secret>`
  + 只存 SHA-256、设备管理端点仅本机可调（新增 `HTTPRequest.isLocalProcess`）。
- ⚠️ 迁移陷阱：`/api/pair` 的 `deviceId` 是**主机** id（iOS 用它做中继精确路由），新增凭据 id 必须另开
  `credentialId` 字段，不能替换。
